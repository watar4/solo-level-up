# 01. 現状分析 ― なぜ「バトルをしようと思えない」のか

実コードを精査した結果、不満①②③はいずれも構造的な原因に還元できる。

## 1. 戦闘システムの問題(不満①)

### 1-1. 「戦う理由」が存在しない

- 現行の戦闘は `src/components/DailyBossPanel.tsx`(1,678行)による**無限タワー**。フロア = `bossesDefeated + 1` で、`src/lib/boss.ts:120` の `pickBossByFloor` が **7体のボスを永遠に循環**させているだけ。
- 報酬はゴールド・影EXP・抽出・宝箱(`boss.ts:335`, `economy.ts:23`, `items.ts:68`)だが、**「次に何が待っているか」という物語的な引きがゼロ**。フロア100もフロア5も、係数が違うだけの同じ絵・同じ行動のボスが出る。
- **ゴールと終わりがない**。ポケモンで言えば「ジムも四天王もなく、野生ポケモンだけが無限に強くなる世界」。クリア目標がないゲームを人は遊び続けられない。

### 1-2. 戦闘と習慣が接続していない

- 習慣クエストの報酬はプレイヤーEXP・ステータス・ゴールド(`useGameData.ts:375`)。戦闘はいつでも無料で挑める。つまり**習慣をサボっても戦闘には一切影響がない**。習慣化アプリの中核要素なのに、習慣と最も疎結合な機能になっている。

### 1-3. 戦闘の中身が単調

- ボスの行動は**通常攻撃1種のみ**(`boss.ts:277` `computeBossAttack`)。状態異常なし、バフ・デバフなし、フェーズ変化なし、特殊技なし。
- プレイヤー側もコマンドは実質「最も倍率の高いスキルを CD 順に押す」だけ。意思決定が発生しない。
- ミニボス(5階ごと、`boss.ts:132`)は HP×1.5 / ATK×1.25 の**係数違いでしかなく、見た目も挙動も同じ**。

### 1-4. UI がモーダルパネルで「戦場感」がない

- 戦闘は Dashboard 内のパネル(`Dashboard.tsx:607` 付近から開くモーダル)として表示され、背景は常に同じシステムウィンドウ。**没入の切り替え(ここから戦闘だ、という舞台転換)が起きない**。

## 2. キャラクリの問題(不満②)

- 作成時に選べるのは**名前・クラス・主色・差し色の4項目のみ**(`CharacterCreation.tsx`)。
- クラス4種(knight/mage/hunter/scout、`types.ts:40`)は**見た目と紹介文だけで、ステータス・スキル・成長に一切影響しない**(`playerSprites.ts:131` の定義参照)。選択に意味がない = 楽しくない。
- アバターは 16×16 の固定グリッドに色を流し込むだけ(`playerSprites.ts:173`)。**髪型も表情も装身具も選べない**。
- 装備は武器1スロットのみ(`items.ts`、5ステ×4レア=20種)。**見た目に反映されない**ため収集欲も湧かない。
- 成長後の楽しみ(転職・上位職・衣装)が存在しない。

## 3. ボスデザインの問題(不満③)

- ボスは `boss.ts:34` の `BOSSES` 配列に**手書き7体で打ち止め**。
- スプライトは 16×16(`bossSprites.ts`)。サイズが小さく「ボスの威圧感」が出ない。プレイヤーと同サイズの敵が"ボス"を名乗っている。
- 全ボスが同一の行動ロジックを共有し、`weak/resist/agility/attack/critChance` の数値差しかない(`boss.ts:22` `BossDef`)。
- 登場演出・撃破演出・セリフ・ロア(背景設定)が `flavor` 一文のみ。**キャラクターとして立っていない**。

## 5. 結論

**足りないのはコンテンツ量ではなく「構造」である。**
「終わりのある物語」「習慣→戦闘の資源接続」「敵の個性」の3点を導入すれば、既存資産の大半はそのまま次の設計に流用できる。以降の章でその構造を定義する。
